# Aion 2 data extraction from the player's own install - options (2026-10-04)

Method: GitHub MCP (repo/code search, file reads) plus WebSearch/WebFetch. Nothing downloaded, cloned, installed or run; the game was not touched. Repo contents were read through the GitHub API only. Not repeated here: the meter/overlay/hack repos already ranked in github_survey.md.
Web search found NOTHING for Aion 2 AES keys, usmap files, or datamine threads (only other UE games). Everything below is from GitHub source.
Unverified throughout: I have not run any tool, so "works on the current global client" is untested.

## Key finding

Aion 2 is Unreal Engine 5.3-based, and it is a FIRST-CLASS supported game in CUE4Parse (the library behind FModel). The game data tables are NOT in the paks as DataTables; they are obfuscated loose `.dat` files under `AION2/Content/Data/...` (Table, Map, WorldMap, MapEvent, MapDataHierarchy) plus localization `L10NString.dat`. CUE4Parse already contains the decoders. So full tables (skills, effects, items, stigma, Daevanion, enchant, recipes - whatever ships as Table `.dat`) can be read from disk, offline, with no running game, no memory reads, no packet capture.

Evidence:
- `GAME_Aion2 = GAME_UE5_3 + 5` in CUE4Parse `EGame.cs`; many Aion2-specific serialization branches (Nanite, landscape, materials, control rig).
- `CUE4Parse/GameTypes/Aion2/`: `FAion2DataTableFile.cs`, `FAion2DataFile.cs`, `FAion2DatFileArchive.cs`, `FAion2KeyManifestFile.cs`, `FAion2L10NFile.cs`, `FAion2MapDataFile.cs`, `FAion2MapHierarchyFile.cs`, `FAion2PropertyReader.cs`, `Encryption/Dat/Aion2DatFileEncryption(.DataTable/.L10N).cs`.
- FModel mainline has an `Aion2` asset category and a `case "dat" when GAME_Aion2` handler (CUE4ParseViewModel.cs).
- `InternationalizationDictionary.cs` calls `LoadAion2L10NDatFiles` for Aion 2 localization.

## Candidates

### 1. FabianFG/CUE4Parse (library) + FModel (4sval/FModel, GUI)
- URL: https://github.com/FabianFG/CUE4Parse (651 stars, pushed 2026-10-04, Apache-2.0). FModel: https://github.com/4sval/FModel (code search hit on Aion2 handling; stars/licence not re-checked here).
- Extracts: UE pak/IoStore (`.pak`, `.utoc/.ucas`) assets, textures to PNG, and Aion 2 `.dat` Table/Map/L10N to JSON. Table decode = key-manifest AES + LZ4 (per uex README), key source is `key_manifest.dat` in the install.
- Needs running game / memory / packet capture: NO. Reads files from disk. ACCEPTABLE.
- Needs from us: the pak AES key (if the paks are encrypted; unconfirmed for global) and a `.usmap` mappings file for UE5 property parsing. A usmap is normally generated by dumping a RUNNING game (UE4SS / Dumper-7 style) - that would be memory/injection and is NOT acceptable under our rule. Look for a community-published usmap (uex example profile references `AION2-5.3.2.0-1.0.34.0.usmap`, i.e. version-specific, so a new global patch needs a matching one). Tables in `.dat` do not appear to need usmap (CUE4Parse reads them with its own reader); only `.uasset` blueprint/UI data does. Unconfirmed.
- Legal: reading and decoding your own install privately is the intended use. Tools are Apache-2.0 (safe to use). The OUTPUT is NCSOFT copyright game data: do not redistribute raw dumps or icons; ship only our own derived numbers/formulas, ideally generated on the user's machine at first run.
- Risk: unknown whether NCSOFT's EULA forbids extracting client files (nothing found either way). No anti-cheat contact: file read only, game closed.

### 2. arkive-games/uex (headless CLI/MCP wrapper over CUE4Parse)  - NEW
- URL: https://github.com/arkive-games/uex (4 stars, pushed 2026-08-27, Apache-2.0, C#, .NET 10).
- Extracts: FModel-compatible export tree. `uex export --profile aion2` walks `AION2/Content/Data` and `AION2/Content/UI`; Aion 2 `.dat` -> decoded `.json` (Table: key-manifest AES + LZ4; Map/WorldMap keystream; MapEvent decrypted JSON; MapDataHierarchy). Byte-identical to FModel output (their claim, unverified by me). Also `list`, `search`, `preview`, `preview-texture`, `serve` (JSON-lines), `mcp`.
- Needs game running/memory/packets: NO. Reads `paksDir` (e.g. `.../Aion2/Content/Paks`) from disk. ACCEPTABLE.
- Needs: .NET 10 SDK, `git clone --recurse-submodules` (pinned CUE4Parse; releases lag, and a missing provider fails silently), `.usmap`, `aesKey`, and network once to fetch Oodle/zlib DLLs. Its example profile is the TW client (`AION2_TW`), so global layout may differ in path only.
- Legal: same as above. It is the same author pipeline as `arkive-games/arkive` (interactive maps, licence NOASSERTION) which publishes derived wiki/map data; that is their exposure, not a clearance.
- Note: running it means downloading and running a tool - that is a decision for Jon, not done here.

### 3. blacksole/Aion2-TM-DesktopApp (data scrapers, reference)  - NEW
- URL: https://github.com/blacksole/Aion2-TM-DesktopApp (2 stars, pushed 2026-10-02, AGPL-3.0, Python).
- Contains `ItemDatabase/fetch_skills.py`, `fetch_recipes.py`, `fetch_daevanion_*.py`, `fetch_arcana_*.py`, `fetch_items.py`, `fetch_dungeons.py`, plus `ENCHANT_RATES.json/.md`. `fetch_skills.py` scrapes gamers4.life public skill pages (`https://gamers4.life/aion-2/database/en/skill/{id}/`; sitemap `.../sitemaps/en-skill.xml`), which expose "Record fields" including `levels[] {level,minValue,maxValue}`, `specializations`, `consumed`, `range`, `requiredWeapons`, `cooldown`, `damageType`. That implies gamers4.life has the full client skill tables (ground-truth shape for what the `.dat` Table decode should produce).
- Enchant rates are EMPIRICAL (117 data points from equipped items via shugo.gg API, not client tables): Legend weapon +10 attack/level cap 15; Heroic weapon +17.5/level cap 20; Heroic armor +35 def and +20 HP per level cap 20; belt cap 10; exceed range +30 attack/level. Treat as a validation target for the extracted enchant table.
- Needs game/memory/packets: NO (web scraping of third-party sites). Not an extractor from our install.
- Legal: AGPL-3.0 code (do not copy into non-AGPL project). Scraping gamers4.life/shugo.gg is a third-party ToS question (not read). Data is NCSOFT's underneath.

### 4. gamers4.life Aion 2 database (site)  - NEW

## What the extraction probably covers vs. not (hypothesis, unverified)
- Likely in `Data/Table/*.dat`: skills, skill levels, skill effects/abnormal effects (the ATK ratio / flat damage / per-rank scaling and the `se_dmg:`/`abe:` token sources behind data_contract.md), likely items, stigma, Daevanion, enchant, crafting tables.
- Likely NOT recoverable from files: server-side formula constants (crit curve, defense formula, drop/enchant success rates computed on server), animation/cast timing (lives in UE animation assets, needs usmap and is exportable as asset data, but cast_time_s = 0 in the current tables suggests the real timing is in montage notifies). Enchant success rates are probably server-side.
- Tables will be in the client's own locale; names come from `L10NString.dat` (reader exists: `FAion2L10NFile`).

## Ranked recommendation (safest practical path)

1. FModel (GUI, release build) on the player's own install, game closed: mount Paks with the right AES key, load a community `.usmap` only if needed for assets, export `AION2/Content/Data/Table` and `L10N`. Lowest effort, official-looking mainline support, nothing resident. Cross-check output field names against phuongtruong97's `Skill.json` and the gamers4.life record fields.
2. arkive-games/uex CLI over CUE4Parse if we want a scripted, repeatable extractor that our app can call (same decoding, `export`/`serve`/`mcp`, Apache-2.0). Better long-term; heavier setup (.NET 10, submodule, one-time DLL download).
3. Third-party dumps (phuongtruong97) and sites (gamers4.life, shugo.gg) as schema reference and validation only, never as the shipped data source.

Constraints for all: no usmap generation from a running game (memory/injection, forbidden); no copying of AGPL/GPL code; do not commit or redistribute extracted tables or icons (NCSOFT IP) - generate on the user's machine, ship only our own derived/aggregated numbers.
