## Skill Ranks And Specialties

- **Local description calculation:** A `Xi/Zi/Qi/$i/ea` `[56819,59085)` substitutes placeholders from backend-supplied `descriptionData`. At a requested level it uses that level's row when present, otherwise `base`; ABE rows similarly fall back to `abeBase`. For direct attack-scaled min/max descriptions, the unformatted value is `base + coefficient * attack / 10000`, floored; multi-hit sum descriptions multiply by `values[4] || 1` **before flooring**. The ABE damage/heal-over-time branch has separate coefficient/multiplier fields and a duration/interval-derived tick display. None of this applies target defense, crit, mitigation or all combat modifiers. These are calculated tooltip numbers, not observed hit results.
- **No effective-rank formula established:** A `[101500,104500)` derives the database card's slider maximum from numeric keys in placeholder `levels`, with minimum 1; it is not evidence of a paid-rank cap, bonus-rank cap or point budget. Selected state is `selectedNodes[boardId] = nodeId[]`; export preserves board/node identity as strings. The node-cost sum is useful as a spent-point cross-check, **not a path validator**. Minification and backend-only logic remain limitations, so literal absence is not proof that Questlog lacks those features elsewhere.

## Built-In Snapshot Export

**Available UI, statically established:** C `[11900,13900)` selects either current character state or a saved character from the desktop `characters` stream, including a saved timestamp; `[19200,19790)` opens the same export modal for the selected character. E `[2766,2920)`, `[4100,4650)` obtains `combat.character` / `combat.characters` through desktop subscriptions. F `[7715,9494)` bridges typed operations through `window.questlogDesktop.listen/send` using the `combat` channel (default `main` for app operations). These are declared IPC/subscription surfaces, not a runtime observation in this sidecar.

C `[2700,3600)`, `[6400,10000)` implements signed-in export to a new website character or an existing same-class character. It calls the **backend** `characterBuilder.importFromGame.mutate`, then desktop `main` operation `app.open.mutate` with the returned `/locale/character-builder/slug` path. It also has `app.signIn`. The inspected modal supplies no local JSON file export/import action; this is a bounded finding about this UI.

**Payload conversions worth validating**, C `[3650,6470)`:

- Equipment slot IDs map to named slots; `lvl = enchant + surpass`. Soul-stat entries are removed from generic gear stats by exact `(stat,value)` match, one occurrence per soul entry; only the first soul stat becomes `soulAdd`. Gear skills become skill-ID substats with null value. This lossy mapping is Questlog export behavior, not a reason for our importer to discard information.
- Manastone values are looked up using `database.getItem` rows at `stats[grade - 1]`; unavailable values become null. Numeric stat IDs are translated by `statFormat`. Arcana uses its own slot mapping, `lvl = enchant`, and explicit skill levels.
- Character fields include class/level, owned skins, monolith tokens, pets, owned wings, owned titles and genus effects; the build includes equipment, arcana, three equipped-title slots and equipped wing. Pantheon decorations are separate. Genus effect slots become one-based string keys.
- Skills preserve `lvl = snapshot.level`, set `slotId:null`, and map specialization ordinals to IDs using `skillId + ordinal * 10`. Daevanion maps each board to string node IDs. This does not establish rank decoding from arbitrary skill-ID suffixes.
- The export payload does **not** include snapshot `stats`, purchased/bonus rank separation, spare skill points or spare Daevanion points. The page renders supplied `stats` separately, C `[12900,13600)`, `[18000,19000)`. Thus exported/recalculated website stats are not an independent copy of the supplied snapshot stat vector. Main's decoder `skillPoints/bonusSkillPoints` lead has no confirmed normalized save path; spare budgets must remain unknown.

## Five Engine Checks

1. **Reconcile stats with provenance:** compare the saved snapshot's supplied stat vector against our recomputation for the same gear/collections/patch, preserving raw units. Exercise numeric-stat translation, percent formatting and missing table rows. Do not compare two recalculations and call the result observed validation.
2. **Audit contribution accounting:** fixture repeated equipment slots/set thresholds, soul-stat duplicate removal, explicit arcana skill levels, enchant/Exceed/potential separation, and all collection sources. Keep snapshot inputs richer than Questlog's lossy export; never treat gear score as combat power or DPS.
3. **Separate purchased rank, bonus rank and selected specialties:** test equipment/arcana/Daevanion bonuses independently, specialty thresholds at either side of an unlock, and ordinary-skill selection versus stigma auto-display. Do not infer effective-rank caps or spare budgets from the slider, exported `lvl`, or decoder fields without a saved-state mapping.
4. **Cross-check tooltip arithmetic only within its scope:** synthetic direct-damage fixtures should use coefficient /10000, level-row fallback and multiplication-before-flooring. Example: base 100, coefficient 3333, attack 101, three hits yields displayed sum 400, versus 399 if each hit is floored first. This is an analyst-derived fixture from Questlog code, not a game damage test.
5. **Validate Daevanion legality separately from spent cost:** support the two effect schemas explicitly; preserve exact board/node IDs; reject duplicate/wrong-board nodes and check roots, connectivity, prerequisites, required levels and available points using our independently sourced graph/budgets. The packaged sum can validate node costs only when matching backend rows are available; it cannot validate an optimal or legal route.
