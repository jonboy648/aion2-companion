# Layout QA: Aion 2 site preview (http://127.0.0.1:5196), 2026-10-05

Scope: report only, no source files edited. Screenshots in `D:\Aion2\.playwright-mcp\qa\` (named `<page>_<width>.png`).
Method: headless Chromium via Playwright (viewport widths 1440 / 1920 for every page, 1280 / 1100 for the header, 390 spot checks). jev-browser was loaded but has no viewport control, so the screenshots came from a Playwright script (scratchpad `shot.cjs`).

Caveats you should know before trusting this:
- Full-page screenshots show the `<body>` background gradient stopping at 1000 px (one viewport) and the sticky header drifting mid-page. Both are full-page-capture artifacts, not site bugs. The header IS sticky (verified, see P1-1).
- Lazy-loaded icons show as empty dark frames in a screenshot taken 2 s after load. I verified on /items/sets that all images do load (6 s); that is a pop-in issue (P3), not broken images.
- **Character page /c/nae/2103/DarthThot cannot load on :5196.** The preview build has `VITE_ARMORY_PROXY_URL` unset ("Armory proxy is not configured"; I waited 64 s, then confirmed in source `src/lib/armory.ts`). /board shows "The board is not available in this build" for the same reason. To still check the Stat sheet and gear-upgrade links I built the same source (`D:\Aion2-preview\web`, branch `preview-five`) in mock-engine mode into the scratchpad (project files untouched, server stopped afterwards). Those character screenshots (`character_*.png`, `statsheet-*.png`) are the DarthThot FIXTURE, not live armory data, so numbers (e.g. "differs from armory", ~0 attributes) are not meaningful; only layout is.
- Console: zero JS errors on every page at every width. Only warning is a WebGL "GPU stall due to ReadPixels" on the home hero (headless GPU, ignore). No 4xx/5xx responses.
- No horizontal page scroll anywhere (scrollWidth == clientWidth on all pages and widths). Wide tables scroll inside their cards (see P2-3).

## P1: broken / ugly

### P1-1 Header is ~177 px tall and sticky (217 px at 1100, 293 px at 390)
- Pages: all. Widths: 1440, 1920, 1280 (177 px), 1100 (217 px), 390 (293 px).
- What: the 13 nav links do not fit on one row inside the 1120 px container, so they wrap: row 1 = 13 links, row 2 = lone right-aligned "Search Ctrl K" button, then the timer strip, then a gold rule. Total 177 px, ~18% of a 1000 px viewport and 22% of an 800 px laptop viewport, and it is `position: sticky; top: 0` (measured), so it stays on screen while scrolling and eats that space permanently. On a phone the nav is 5 rows and the sticky header is 293 of 844 px (35% of the screen), and the timer strip drops "Siege Bosses" and "Daily reset".
- Screens: `sticky-header-scrolled_1440.png`, `home_1440.png`, `home-viewport_1100.png`, `home_390.png`.
- Fix: group the links (see Navigation section) so the bar is one row of ~6 items plus Search; make the timer strip a slim 28 px row inside the same sticky block or stop making the header sticky (keep only the thin timer strip sticky). On mobile collapse nav into a hamburger/drawer and keep a single 56 px bar.

### P1-2 Daevanion and Codex take ~7-8 s to show anything, with only a text "Loading boards..." / "Loading skills..."
- Pages: /daevanion, /codex, /codex/sorcerer. Width: all (measured at 1440; 8.0 s, 8.0 s, 6.7 s until "Loading" disappeared; other pages 2.3 s).
- What: the page frame renders, then a bare text line on a ~500 px empty area for many seconds. Any visitor who checks after 3 s will think it is broken.
- Screens: `daevanion_1920.png` was captured in this state at first (re-captured loaded after 11 s); the loading state is visible in the first-pass screenshots described in the text of this report.
- Fix: show a skeleton (Daevanion: the board's square outline + tab placeholders; Codex: 12 ghost cards, as /roadmap already does with empty ornate cards) and look at why the chunk takes 6-8 s on a local server (likely a big JSON/engine chunk fetched before first render). Prefetch on nav hover.

### P1-3 Gear viewer / items tables: content clipped on the right with no scroll hint
- Pages: /items/sword (1440, 1920), /gear-viewer (all widths), item tables at 390.
- What: the table is wider than its card. At 1920 the "ACCURACY" header is cut to "ACCURAC" and the value column shows "15" (really 150). Nothing indicates the card scrolls sideways (no fade, no scrollbar visible until hover, no sticky Item column). On a phone the Grade column is already cut off ("Unic").
- Screens: `items-sword_1920.png`, `gear-viewer-pinned_1920.png`, `items-sword_390.png`.
- Fix: make the Item column sticky-left, add a right-edge fade/shadow when scrollable, and drop low-value default columns (Min attack, Block) at narrow widths. Better: let the items layout use the full width at >= 1440 (see P2-1) so the table fits.

### P1-4 Duplicate rows everywhere in the item database and search
- Pages: /items/sword, /gear-viewer, Ctrl+K "ludra".
- What: nearly every item appears twice with identical name, stats and icon (Ludra's Scale Sword x2, Splendent Ebony Dragon Lord Longsword x2, ...). Count says "154 sword" but it is really ~77 distinct names. Search results show "Ludra's Claw" twice, indistinguishable. Pinning one of a duplicate pair gives a confusing compare table. Item detail pages for the two ids (110220003 and 110220014) look the same.
- Screens: `items-sword_1920.png`, `gear-viewer-pinned_1920.png`, `search-ludra_1920.png`.
- Fix: dedupe in the data build by (name, stats, level) or label the variant (e.g. a small "Global"/"KR"/"Tradable" tag), and dedupe the search index. If the two ids are legitimately different (bound vs tradable), show that column.

### P1-5 Stat sheet: unrounded axis label and layout gap
- Page: character page, 1440 and 1920 (fixture). Also outside the new card: the "Estimated damage by skill" bar chart.
- What: x-axis end tick reads `1206248.2290059885` (raw float). Within Stat sheet, categories are laid out as a 2-column grid where each row is stretched to the taller card: "Deity (Conqueror) Points" is collapsed but its row is as tall as an open "Attributes", leaving a ~250 px dead column on the right; same under "Critical and special hits" / "PvE and boss". Hover expands a source panel inline, pushing every row below it down (layout shift) instead of overlaying.
- Screens: `character_1920.png`, `statsheet-open_1440.png`, `statsheet-hover_1440.png`.
- Fix: round/`toLocaleString` the tick (or use "k"); use a CSS columns/masonry layout or `align-items: start` so collapsed cards do not stretch; show sources as a popover/side panel anchored to the stat (absolute-positioned), not an in-flow block.

## P2: inconsistent

### P2-1 Everything is capped at 1120 px; at 1920 there are ~400 px dead gutters per side
- Pages: all, esp. /items*, /gear-viewer, /crafting, /roadmap, /enhance at 1920. The home hero is full-bleed, so the site contradicts itself.
- Fix: keep prose at 1120, but allow data pages (items, gear viewer, codex, crafting, daevanion) a wider container (1480-1680 px). At 1920 /items/sword would then fit all stat columns (fixes P1-3), Codex could show 4 columns, Crafting 2 columns.

### P2-2 /crafting is a single 3,620 px column of near-identical cards
- 1920 and 1440: 27 recipe cards, each one row of content, stacked in the left 60% of the page; the Shopping list on the right is short and empty. Cards use the ornate frame so the repetition is heavy.
- Screen: `crafting_1920.png`.
- Fix: 2-column recipe grid at >= 1280, a lighter card style (no corner ornaments) for list rows, and keep Shopping list `position: sticky`. (I did not verify it is already sticky.)

### P2-3 Heading colors: new item pages use teal group headings; rest of site uses gold
- /items, /items/*: the left category rail headings (WEAPONS, ARMOR, ACCESSORIES...) are bright cyan small caps, inside a gold-cornered frame; the "Where to get it" chips and breadcrumbs are cyan while page H1s are gold. /maps card titles ("AION2 HUB MAPS") are also cyan. Not wrong, but /items looks like a different product from /enhance and /checklist.
- Fix: use the gold small-caps style used by "Recipes", "Level and stats" for category headings; reserve cyan for links.

### P2-4 Items rail: the "All categories" pill touches the "WEAPONS" heading
- /items*, 1440 and 1920 (`items-sets_1440.png`): no vertical gap between the pill and the heading. The rail is also 1150 px tall (14 consumables/misc categories with counts) so on /items/sets it is taller than the content. 
- Fix: 8-12 px margin; collapse Consumables/Misc groups by default; make the rail `sticky` or `max-height` with its own scroll.

### P2-5 Filter bars differ between /items, /items/sword and /gear-viewer
- /items has Class select but wraps "Item level" onto its own row; /items/sword has no Class select and a different wrap; labels sit at different heights ("Search" label above, but "Grade"/"Level" labels inline). Result: three different layouts for the same filters.
- Screens: `items_1920.png`, `items-sword_1920.png`, `gear-viewer-empty_1920.png`.
- Fix: one shared filter-bar component with a fixed grid (Search | Grade chips | Level | Item level | Class | Type) that wraps as a group.

### P2-6 /timers: 11 cards in a 2-column grid leave an orphan card; repeated rows
- 1920 and 1440 (`timers_1920.png`): last "Weekly reset" card sits alone with an empty right half. Weekly reset lists "Wed 11:00 AM" five times and "Daily reset" lists five consecutive days, which reads as filler; Guardian Lord Nahma alternates Fri/Sun repeatedly. Card heights differ by row (description lengths), so rows are uneven.
- Fix: 3 columns at >= 1440 (11 cards -> 4+4+3 is better than 5 rows + orphan), cap repeated rows at the next 3 distinct, and use `grid-auto-rows: 1fr` for even heights.

### P2-7 Timer strip: tiny, centered while the nav above is left-aligned
- Strip text is ~12 px, centered under a left-aligned logo/nav, inside a narrower (1150 px) rule than the content (1120) with inconsistent side margins to the gold rule below. At 390 only 2 of 4 timers fit.
- Fix: left-align or space the four timers across the container width, 13-14 px, and allow horizontal scroll or wrap on phones.

### P2-8 Search palette: relevance and default selection
- Ctrl+K "ludra": the Daevanion section fills with "Skill Level Up - Drill Dart / Divine Aura..." which do not contain "ludra" (matched on node descriptions, presumably); "fire" returns "Faith Greaves/Greatsword/Breastplate" and "Fallen Ancient God Ruby Necklace". The first, pre-selected result for "fire" is the "Find your best Aion 2 build" page entry, so Enter jumps to the home page rather than to Fire Wall.
- Visual: panel itself is clean (width 575, rounded gold border, good contrast, footer hint), but the last row is cut mid-text without a scroll fade.
- Screens: `search-ludra_1920.png`, `search-fire_1440.png`.
- Fix: stricter fuzzy threshold, rank exact/prefix name matches first, never put the generic Pages hit above specific hits, label duplicate items, add a bottom fade.

### P2-9 Empty / unavailable states are plain and differ page to page
- /keybinds (centered card with CTA, good), /board ("The board is not available in this build" plain text, large empty area; this is a preview-config issue but the production empty state should not look like that), /checklist (three stacked ornate cards each saying "No daily tasks yet" with duplicated "Add" rows), /daevanion "Running totals" (a full ornate card for one sentence).
- Fix: shared EmptyState component, collapse empty checklist sections into a single "Start with a pack" prompt.

### P2-10 Roadmap duplicates content
- /roadmap level 22: one summary line lists the 13 stigma skills, then 13 separate "Unlock X" lines repeat them (a 300 px block). Level circles and cards are fine.
- Fix: collapse the 13 unlock rows behind a "Show 13 skills" disclosure.

### P2-11 Character page: Stat sheet and Gear upgrades rows
- Gear upgrades list (10 rows) is clean; the new "Cost to reach +N" text is a 9-10 px link at the right edge of the row (`character_1920.png`, y~1500-1740): tiny, low contrast against the card, and not obviously clickable. Links go to `/enhance?item=...&track=enchant&from=..&to=..` correctly (4 verified in markup, not clicked through).
- Fix: render as a visible small button/pill with an arrow, 12 px minimum.

## P3: polish

1. Icon pop-in: item/set/search icons load late; empty dark frames show for several seconds (/items/sets, /items/sword at 390). Add a faint skeleton shimmer and set `width/height` to avoid layout shift. The `loading="lazy"` icons below the fold are fine, but those in the first viewport should be eager.
2. Items table: 28 px icon + gold name + gold "Unique" repeated 100 rows, name column left but numeric columns not tabular/right aligned consistently ("525" right aligned, "420" centered-ish). Use `tabular-nums` and right-align all numeric headers and cells.
3. /codex: "TD", "HL", "HM", "FZ" two-letter placeholder tiles instead of icons for a few skills (Hellfire Level 1/2/Max, The Depths, Flame Zone). The "confirmed / estimated / unknown" pills are tiny (10 px).
4. /enhance: left Item card ends at y~850 while the right column runs to 1300; the form is not sticky so the left half is empty while you read results. Make the Item card `sticky top-[header]`. Chart x-axis labels fine; "Dashed lines" legend is a footnote, could be inline legend.
5. /enhance at 390: the Step-by-step table has `min-w-[25rem]`, scrolls inside the card, fine but scroll affordance absent (same as P1-3).
6. /checklist: the info banner text is 11 px at full 1120 width (long line, ~190 characters). Constrain to ~75ch and bump to 13 px.
7. /maps: party map grid has no labels or axis; empty blue box 1120x700. Add placeholder text "Click to drop a pin".
8. Footer is missing "Home", "Items", "Compare" (footer has "Compare builds"), "Maps" is footer only (see Navigation). Footer groups ("Build & plan / Learn & explore / Community") are a ready-made grouping for the header. Footer link text is 13 px grey, fine. No /items link in footer.
9. Home at 390: 3 of 8 class cards (Assassin, Sorcerer, Cleric, Chanter) render as empty gradients in the full-page capture (lazy load; will fill on scroll). Worth confirming with a real scroll test; I did not.
10. "mock data" badge in header only in my mock build (ignore).
11. Typography: H1 gold small-caps with swoosh (good, consistent on all pages); H2 inside cards is smaller white small-caps, and on /guide H2 is gold with swoosh again, so the "second level" style is not consistent between /guide, /checklist and /enhance.
12. Active nav state: gold outline + gold text, works on every page (Items stays active on /items/sword, /items/sets and item detail; Codex active on /codex/sorcerer). Hover state not checked. /gear-viewer and /board and /maps have no nav item to highlight (Gear viewer lives under Items but the nav shows nothing active at /gear-viewer; I saw no highlighted link in `gear-viewer-pinned_1920.png`).

## Navigation

Current: 13 links (Home, Start here, Build, Daevanion, Compare, Codex, Items, Keybinds, Crafting, Enhance, Road Map, Timers, Checklist) + Search; wraps to two rows at 1280-1920 and five rows at 390. Board and Maps exist in the footer only, Gear viewer is only reachable from Items.

Recommendation: logo + 5 top-level items + Search, one row, no wrap, reuse the footer's grouping so header and footer agree.

| Top-level | Contains |
|---|---|
| Start here (plain link) | Start here, Road Map |
| Plan (dropdown) | Build, Compare, Daevanion, Keybinds |
| Database (dropdown) | Codex, Items (with Item sets, Gear viewer), Crafting, Enhance calculator |
| Live (dropdown) | Timers, Checklist, Maps, Board |
| Search (button, Ctrl K) | |

Notes:
- Home is the logo; drop the separate "Home" link.
- The timer strip belongs next to "Live > Timers"; keep it as a slim single line, left-aligned under the bar.
- Keep Search as the always-visible button; on mobile reduce to icon + hamburger.
- Dropdowns open on click (not hover) so touch works; the active top-level should light up when any child route is active (Items children, Gear viewer, Codex classes).
- Alternative if dropdowns are unwanted: two-tier bar (primary row of 5 groups, secondary row of the group's children shown only on pages in that group); the vertical cost is the same as today but only when inside a group.
